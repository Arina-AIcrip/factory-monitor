# КОНТУР — веб-дашборд мониторинга показателей

Кейс № 8 номинации «Программирование (разработка мобильных и веб-приложений)».
Учебная панель диспетчера производства: четыре KPI, линейный и столбчатый графики, фильтры, состояние оборудования и журнал событий.

## Открыть готовый сайт

https://factory-monitor-rkr2.onrender.com/

Исходный код: https://github.com/Arina-AIcrip/factory-monitor

Для просмотра сайта установка не нужна. На бесплатном Render после простоя первое открытие может занять около минуты.

## 1. Как открыть на Windows

1. Полностью распакуйте архив в обычную папку. Не запускайте приложение внутри ZIP.
2. Установите Node.js версии 22 или новее с https://nodejs.org/ (проверено на Node.js 24.22.1).
3. Откройте папку `factory-monitor` и дважды нажмите `START.cmd`.
4. Оставьте открытым окно сервера. В браузере откройте **http://127.0.0.1:3008/**.
5. Для остановки нажмите Ctrl+C в окне сервера.

Установка npm-пакетов не нужна. Библиотека графиков включена в архив. После установки Node.js интернет для локальной работы не требуется. Логин и пароль не нужны.

Если Windows не запускает START.cmd, откройте папку проекта в Проводнике, введите `powershell` в адресной строке и нажмите Enter. Выполните:

```powershell
node --version
node server.mjs
```

Для macOS/Linux откройте терминал в папке проекта и выполните ту же команду `node server.mjs`.

Если порт занят, остановите старый сервер или в PowerShell задайте другой:

```powershell
$env:PORT = '3010'
node server.mjs
```

Тогда адрес будет http://127.0.0.1:3010/. Открывать `public/index.html` двойным щелчком не нужно: интерфейсу требуется API работающего сервера.

## 2. Что показывает приложение

- **Выпущено продукции:** сумма выпущенных изделий выбранных линий за период, включая изделия с браком.
- **Доступность линий:** доля пятисекундных измерений, в которых линия работала. Для нескольких линий считается по всем измерениям всех выбранных линий.
- **Энергопотребление:** сумма энергии выбранных линий, кВт·ч.
- **Доля брака:** число бракованных изделий / общий выпуск × 100%.
- **Динамика выпуска:** линейный график. Интервалы агрегации: 1 минута для часа, 7,5 минуты для 6 часов, 30 минут для суток.
- **Энергия по линиям:** столбчатый график суммарного потребления каждой выбранной линии.
- **Производственные линии:** текущее состояние и температура; выпуск за выбранный период. Предупреждение отображается при температуре выше 75 °C, остановка — по состоянию источника.
- **Последние события:** до 20 событий, отсортированных от новых к старым, с объектом, уровнем и описанием.

Время отображается в часовом поясе Москвы. Фильтры «Период» и «Объект мониторинга» одновременно применяются ко всем виджетам. Состояние линии — на конец периода, а суммы относятся ко всему периоду.

## 3. Как проверить и продемонстрировать

1. Откройте главную страницу. Покажите четыре показателя, оба графика и таблицу событий.
2. Запомните время обновления. Подождите 6–10 секунд: время и данные обновятся без перезагрузки страницы. Некоторые округлённые значения могут не измениться на каждом опросе.
3. Выберите «Линия сборки». Останется одна карточка и один столбец, события будут только по этой линии.
4. Выберите «Последние 24 часа». Все суммы и интервал линейного графика изменятся для нового периода.
5. Нажмите **«Проверить потерю связи»** внизу страницы. Появится предупреждение, последний снимок останется на экране. Это явно обозначенная имитация ошибки клиентского запроса.
6. Во время имитации измените фильтр. Предупреждение укажет, к какому старому фильтру относится сохранённый снимок.
7. Нажмите **«Восстановить связь»**. Будет загружен новый снимок с актуальными фильтрами, появится сообщение о восстановлении.
8. Для проверки настоящего разрыва остановите сервер через Ctrl+C, оставив страницу открытой. Нажмите «Обновить»: появится ошибка связи. Снова выполните `node server.mjs`. Интерфейс подключится автоматически (повторные попытки до 15 секунд, тайм-аут отдельного запроса 7 секунд) или после кнопки «Обновить».
9. Уменьшите окно браузера до ширины телефона. Карточки перестроятся; широкую таблицу можно прокручивать внутри её блока.

## 4. Источник данных и ограничения

Это **учебная имитация производства**, не подключение к реальным станкам. `telemetry.mjs` рассчитывает показатели для трёх линий: резки, сборки и упаковки. Один замер соответствует 5 секундам, глубина истории — до 24 часов. Для одинаковых времени и фильтров результат воспроизводим. Перезапуск сервера не требует накопления суточной истории.

История событий также синтетическая: она демонстрирует уровни важности, сортировку и фильтрацию; не является журналом реальных аварий и не выводится из температурных замеров. Во время отсутствия связи старые значения нельзя считать актуальными — интерфейс показывает предупреждение.

У приложения нет авторизации, реальной телеметрии, записи истории в БД и уведомлений по почте. Для данного учебного кейса используется допустимая имитация потока. Для промышленного применения понадобятся реальные датчики, постоянное хранилище, контроль доступа и отдельная проверка нагрузки.

## 5. Технологии и устройство

- Node.js, встроенный HTTP-сервер и REST API; сторонних серверных зависимостей нет.
- HTML, CSS, JavaScript; адаптивный интерфейс без сборки.
- Chart.js 4.4.8 — локальная библиотека графиков с лицензией MIT (`public/vendor/Chart-LICENSE.md`).
- Polling: браузер получает единый снимок каждые 3 секунды. При ошибках интервал повторов растёт до 15 секунд.
- Отмена старого запроса и номер запроса предотвращают подмену нового фильтра запоздалым ответом.

Описание API и потока данных: `docs/ARCHITECTURE.md`. Проверка требований: `docs/ACCEPTANCE.md`. Скриншоты: `docs/desktop.png`, `docs/mobile.png`, `docs/offline.png`.

## 6. Автоматические проверки

В папке проекта выполните:

```powershell
node --test tests/dashboard.test.mjs
```

Проверяются согласованность сумм, фильтры, границы периода, воспроизводимость источника, изменение потока, валидация API, методы HTTP и доступность файлов интерфейса.

## 7. Размещение в интернете

Локальный адрес `127.0.0.1` работает только на компьютере с запущенным сервером. Публичная версия: https://factory-monitor-rkr2.onrender.com/.

Проект готов к размещению как Node.js Web Service: команда проверки `node --check server.mjs`, запуска `node server.mjs`. Сервер использует переменную `PORT` хостинга и слушает `0.0.0.0`. Файлы можно загрузить в отдельный GitHub-репозиторий. Данные в файлы не записываются, секреты для запуска не нужны.
